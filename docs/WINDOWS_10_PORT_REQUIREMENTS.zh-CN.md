# Palmier Pro Windows 10 版本移植需求

> 状态：需求草案
> 基线：macOS v0.6.16，仓库提交 `457e853a789e16eb104a0bfb43d2485d9e1ac0c8`
> 目标平台：Windows 10 22H2（19045），x64
> 核心原则：优先保持项目、编辑结果和 Agent 能力兼容；允许界面遵循 Windows 交互习惯，不以逐像素复刻 macOS 为目标。

## 1. 背景

Palmier Pro 当前是面向 macOS 26 和 Apple Silicon 的 AI 原生视频编辑器，使用 Swift 6.2、SwiftUI、AppKit、AVFoundation、Core Image、Metal、Core ML、Speech、MLX、Keychain 和 Sparkle 等 Apple 平台技术。

当前项目约包含 370 个 Swift 源文件和 145 个测试文件。其中，大量 UI、项目文档、播放、渲染、音频、导入导出、字幕、搜索和更新代码直接依赖 Apple 框架，无法通过调整 Swift Package 平台声明直接编译到 Windows。

因此，Windows 版本应视为“保留产品能力、项目格式和服务协议的跨平台重实现”，而不是对现有 SwiftUI 应用做条件编译。

## 2. 项目目标

### 2.1 产品目标

在 Windows 10 上提供可用于真实视频项目的 Palmier Pro 版本，使用户能够：

1. 创建、打开、编辑、保存和导出 Palmier Pro 项目。
2. 完成多轨视频、音频、图片、文字、字幕、Lottie 和嵌套时间线编辑。
3. 使用当前主要剪辑、变速、关键帧、调色、特效、混合、音频与字幕能力。
4. 继续使用内置 Agent 和本地 MCP 服务操作同一个项目。
5. 使用现有生成式 AI、云端转录、账户和项目活动服务。
6. 在 macOS 与 Windows 之间交换项目；平台支持的能力应产生一致的编辑语义和接近一致的画面、声音与导出结果。

### 2.2 成功指标

- Windows 版可完成“导入素材 → 剪辑 → 调色/字幕 → 保存 → 关闭重开 → 导出”的完整流程。
- Windows 版可无损读取当前 `.palmier` 项目结构中的 `project.json` 和 `media.json`。
- Windows 保存的项目可由兼容版本的 macOS 客户端重新打开，且时间线结构、稳定 ID、关键帧、文字、特效参数、生成记录和媒体引用不丢失。
- P0 功能不存在仅在界面层生效、导出失效，或 UI、Agent、撤销使用不同业务规则的情况。
- 代表性 1080p H.264 项目能够流畅预览；无法实时播放时可自动降低预览质量，但不得改变最终导出结果。
- MCP 工具发现、调用、结果回读和撤销在 Windows 上通过端到端验证。

## 3. 范围与优先级

### 3.1 P0：首个可发布版本必须具备

- 项目管理、项目兼容、自动保存、另存为、关闭保护和崩溃恢复。
- 媒体导入、项目内媒体、外部媒体、离线检测、重新链接、缩略图和波形。
- 多轨时间线、基础剪辑、波纹编辑、覆盖编辑、分割、移动、修剪、链接和撤销/重做。
- 视频、音频、图片、文字、字幕和嵌套时间线。
- 预览、播放、暂停、逐帧、拖动播放头、音量控制和音频电平。
- 变换、裁剪、透明度、速度、音量、淡入淡出、关键帧和混合模式。
- 当前基础调色与视频效果的 Windows 等价实现。
- H.264、H.265 视频导出和 XML/FCPXML 项目交换。
- 本地 MCP HTTP 服务及核心编辑工具。
- 现有账户登录、生成式 AI、云端转录和生成结果写回项目。
- 简体中文和英文界面；其他现有语言在文本资源可复用的前提下随版本提供。

### 3.2 P1：公开测试版前完成

- 多机位、音视频自动同步、节拍检测、静音删除、逐词编辑。
- 本地语义视觉搜索和语音内容搜索。
- 本地转录和本地音频降噪。
- ProRes、10-bit HDR 导入、预览和导出。
- Lottie 完整预览、编辑和导出一致性。
- 内置 Agent 面板、技能目录和完整 MCP 工具集。
- 更新检查、差分或完整包升级、失败回滚。

### 3.3 P2：可延期但必须在界面中明确标识

- 与 macOS 完全一致的字体排版和系统字体替代。
- 依赖 Apple 专有模型、编解码器或色彩管线且尚无可靠 Windows 等价实现的能力。
- Windows on ARM。
- Windows 11 专属外观或系统集成。

P1/P2 功能未完成时，Windows 客户端仍必须安全保留对应项目数据。不得在打开、编辑或保存项目时静默删除未知字段、未知效果、未知生成参数或暂不支持的媒体属性。

### 3.4 不在本次范围

- 重构或更换现有云端生成式 AI 后端。
- 新增埋点、遥测或额外网络请求。
- 移动端、Linux 和 Web 版本。
- 将 macOS 与 Windows 的系统菜单、窗口控件和快捷键做逐像素一致。
- 为迁就 Windows 改变现有 MCP 工具名、参数语义或稳定 ID。

## 4. 目标运行环境

### 4.1 最低配置

- Windows 10 22H2，Build 19045，64 位。
- 支持 Direct3D 11 Feature Level 11_0 的 GPU。
- 4 核 CPU、8 GB 内存、安装盘外至少 5 GB 可用空间。
- 1920 × 1080 显示器。
- 可用的系统音频输出设备。

### 4.2 推荐配置

- 8 核或以上 CPU、16 GB 或以上内存。
- 具备 4 GB 或以上显存的 NVIDIA、AMD 或 Intel 独立/集成 GPU。
- SSD 和至少 20 GB 可用缓存空间。

### 4.3 架构建议

建议以以下技术路线作为原型基线，最终选择需通过第 12 节的技术验证门：

- UI：Qt 6 + QML/Qt Quick，使用 Windows 原生窗口、菜单、文件选择器和拖放行为。
- 领域核心：C++20，承载项目模型、时间线计算、校验、编辑操作、撤销、持久化和 Agent 工具共享逻辑。
- 媒体：FFmpeg/libavformat/libavcodec/libavfilter，统一探测、解码、编码和封装。
- GPU：Direct3D 11 + HLSL；硬件解码优先使用 D3D11VA，编码按设备使用 NVENC、Intel QSV 或 AMD AMF，并提供软件回退。
- 音频：WASAPI，必要时通过 FFmpeg 重采样和混音。
- AI 推理：ONNX Runtime + DirectML；CPU 为兼容回退。
- 凭据：Windows Credential Manager。
- 更新：支持签名校验和回滚的 Windows 更新器。

禁止在 UI、MCP 和导出路径中各自实现一套时间线、效果、字幕或布局计算。

## 5. 项目与数据兼容

### 5.1 `.palmier` 项目

- Windows 版必须支持当前目录型 `.palmier` 项目包。
- 必须读取并保留 `project.json`、`media.json`、`thumbnail.jpg`、`media/` 和聊天会话文件。
- 必须兼容当前多时间线项目，以及历史裸 `Timeline` 格式。
- 新增字段必须可选、带默认行为，并定义项目格式版本和迁移策略。
- 保存必须采用“完整暂存 → 同卷准备 → 原子替换”，不得直接覆盖正在使用的项目内容。
- 保存、自动保存、另存为、媒体安装、生成结果写入、关闭和退出必须由同一项目协调器按目标项目串行化。
- 用户取消、磁盘不足、权限失败、文件占用、外部修改或程序崩溃时，最近一次成功保存的项目必须保持可打开。

### 5.2 跨平台路径

- 项目内媒体一律使用相对路径和 `/` 作为序列化分隔符。
- 外部绝对路径保留原值，并额外记录可跨平台匹配的文件名、大小、修改时间和可选内容指纹。
- macOS 路径在 Windows 上不可用时，素材显示为离线，不得改写或删除原路径。
- 重新链接支持单文件、目录批量匹配和内容指纹匹配；成功后只更新媒体解析信息，不改变素材稳定 ID。
- Windows 文件名保留字、大小写差异、长路径、UNC 路径、可移动磁盘和网络盘必须有明确行为。

### 5.3 时间与数值

- 时间线仍以整数帧为权威时间单位。
- 速度、修剪、淡入淡出、关键帧、字幕词级时间和导出换算必须定义与 macOS 相同的舍入规则。
- 所有外部输入在算术、索引和类型转换前验证有限值、范围和溢出。
- 未变化、失败、拒绝和取消的操作不得创建空撤销步骤或修改项目脏状态。

## 6. 功能需求

### 6.1 首页与项目生命周期

- 新建、打开、最近项目、删除记录、项目缩略图和示例项目。
- 自动保存、手动保存、另存为、关闭确认、退出等待和恢复异常中断项目。
- 同一项目不得被多个本地进程无提示地同时写入。
- 项目切换时取消或隔离属于旧项目的缩略图、索引、转录、生成和导出完成回调。
- 用户可查看长任务状态、取消任务，并看到明确的成功、失败、拒绝或取消结果。

### 6.2 媒体库

- 支持拖放、文件选择、粘贴图片、目录递归导入、HTTPS URL、Base64 小文件和纯色遮罩。
- 首版至少支持：
  - 视频：MOV、MP4、M4V。
  - 音频：MP3、WAV、AAC、M4A、AIFF/AIFC、CAF、FLAC。
  - 图片：PNG、JPG/JPEG、TIFF、HEIC/HEIF。
  - 动画：Lottie JSON。
- 导入时异步读取时长、分辨率、帧率、音轨、旋转、色彩和 alpha 信息。
- 缩略图、波形、转录和视觉索引按需生成，具备容量上限、缓存键、失效和取消策略。
- 支持文件夹创建、移动、重命名和删除；删除被引用素材时必须显示影响并保证一个撤销动作完整恢复。

### 6.3 时间线编辑

- 支持视频轨、音频轨、隐藏、静音、同步锁定和轨道高度调整。
- 支持选择、框选、前向选择、吸附、缩放、水平/垂直滚动和播放头跟随。
- 支持添加、插入、覆盖、移动、复制粘贴、分割、修剪、滑移、波纹删除和区间删除。
- 支持音视频链接、链接组、多选原子编辑和跨轨移动。
- 支持多时间线标签、嵌套时间线和循环引用防护。
- 支持多机位素材组、角度切换和音视频同步。
- UI 预览、提交、撤销、MCP 工具和导出必须调用同一领域操作。
- 一个用户意图只产生一个可理解、可完整恢复的撤销动作。

### 6.4 预览、播放与声音

- 支持最终合成预览、源素材预览、逐帧、变速播放、播放头拖动和滑移双画面。
- 支持无音频、无视频、损坏、离线、旋转、透明、可变帧率和非标准采样率素材。
- 播放器不得在 UI 线程执行文件访问、解码器创建、模型推理或同步等待。
- 音频支持混音、音量关键帧、淡入淡出、静音、拖动试听和电平显示。
- 设备拔插、睡眠/唤醒、窗口最小化、项目关闭和应用退出必须正确停止或恢复媒体管线。
- 预览降质仅影响交互性能，不得写入项目或降低最终导出质量。

### 6.5 画面、文字与效果

- 支持位置、尺寸、旋转、裁剪、透明度、圆角、边缘柔化、速度及其现有关键帧能力。
- 支持当前 16 种混合模式（包括 `normal`，即 source-over 基线），并确保 alpha 语义和图层顺序一致。
- 支持文字内容、字体、字号、宽高缩放、字距、行距、大小写、粗体、斜体、下划线、删除线、上划线、颜色、对齐、阴影、背景和描边。
- 支持现有文字动画：淡入、弹入、上滑、打字机、逐词显现、逐词滑入、逐词弹入、词循环、高亮弹出和高亮块。
- Windows 缺少项目字体时，必须提示替代字体；保存时保留原字体名。导出不得静默使用不同字体而不提示。
- Windows 版需按相同效果 ID、参数范围、默认值和顺序实现：
  - 曝光、对比度、饱和度、色温/色调、高光/阴影、黑白场、自然饱和度。
  - 色轮、色相曲线、LUT、曲线。
  - 高斯模糊、锐化、降噪、运动模糊。
  - 反相、胶片颗粒、暗角、辉光、清晰度、色度键。
- 不支持的未知效果必须旁路预览、保留全部参数并显示警告，不能从项目中删除。

### 6.6 字幕、转录与音频分析

- 支持本地和云端转录的统一结果结构，包括文本、语言、词级时间和说话人。
- 支持字幕创建、字幕预设、词级映射、逐词删除和重新生成。
- 支持静音检测与删除、节拍检测、音视频相关性同步和音频降噪。
- 本地模型不可用时允许显式切换云端能力；不得无提示上传素材。
- 本地转录、视觉搜索和降噪使用的模型必须有版本、校验和、下载进度、取消、清理和失败重试。

### 6.7 搜索

- 支持媒体名称和元数据搜索。
- P1 支持当前“视觉语义 + 语音内容”双通道搜索语义。
- Windows 模型应使用与当前 SigLIP2 模型等价的 ONNX 权重和相同 tokenizer，或通过黄金样本证明替代模型的检索结果达到约定阈值。
- 索引过程必须限流、可取消、可恢复，不得因单个损坏素材使整个项目索引失败。

### 6.8 导出

- P0 支持 H.264、H.265、XML 和 FCPXML；P1 支持 ProRes 和 HEVC 10-bit HDR。
- 支持 720p、1080p、2K、4K 和匹配时间线，保持宽高比并输出偶数尺寸。
- 预览与导出共享效果、文字、变换、嵌套、混合和时间换算逻辑。
- 硬件编码不可用、驱动不兼容或编码器初始化失败时，允许回退软件编码并明确提示。
- HEVC 不得依赖用户另购 Microsoft HEVC 扩展；发布包需明确自身编解码能力与许可边界。
- 导出任务支持排队、进度、取消、失败原因、输出覆盖确认和完成后打开位置。
- 取消或失败不得留下看似成功的最终文件；临时文件必须清理。

### 6.9 Agent、MCP 与生成式 AI

- Windows 版继续在 `127.0.0.1:19789` 提供 MCP HTTP 服务，仅绑定 IPv4 回环地址。
- 保持当前工具名、输入字段、稳定 ID、校验规则、结构化回执和撤销语义。
- 至少覆盖项目、时间线、媒体、轨道、剪辑、关键帧、布局、多机位、转录、文字、字幕、调色、特效、降噪、生成和导出工具。
- MCP 修改必须通过与 UI 相同的领域操作和撤销历史。
- 每次调用必须返回明确的 changed/no-op/warnings/skipped/error 状态；不得将后台失败隐藏在成功响应之后。
- URL 导入、生成、转录和导出等长任务必须返回可查询的任务状态。
- 生成视频、图片、音频和放大继续使用现有后端协议；生成结果通过项目协调器写入项目。
- 登录凭据只能保存在 Windows Credential Manager，不得写入日志、项目文件、崩溃报告或明文配置。

## 7. Windows 交互要求

- 界面信息架构保持首页、媒体区、预览区、检查器、Agent 面板和时间线。
- 使用 Windows 标准窗口、菜单、对话框、焦点、键盘导航和高 DPI 行为。
- 保留与 macOS 对应的编辑快捷键，并将 Command 映射为 Ctrl；与 Windows 系统快捷键冲突时单独记录。
- 支持鼠标、触控板滚轮、Shift/Ctrl/Alt 修饰键、Esc 取消、Enter 确认和 Delete 删除。
- 拖放必须区分媒体库导入、素材入轨、时间线移动和文件夹整理，不允许父级接收器遮蔽内部目标。
- 支持 100%、125%、150%、175% 和 200% DPI；跨显示器移动时布局和指针命中区域正确更新。
- 默认保持深色编辑界面；所有样式从统一设计令牌获取，不在业务视图硬编码间距、字号、颜色、圆角、透明度和动画时长。

## 8. 非功能需求

### 8.1 正确性与可靠性

- 所有项目变更必须在保存、导出、撤销和 MCP 回读时保持同一结果。
- 长任务在开始前、执行中、完成后提交前和等待资源时均可取消。
- 后台结果提交前重新确认项目、时间线、素材、配置和任务代次仍有效。
- 相同项目和输出目标的文件操作串行化；并发解码、导出、缩略图和模型推理必须有资源上限。
- 不使用 UI 线程进行文件 I/O、媒体探测、解码、编码、模型推理、索引或大集合转换。

### 8.2 性能目标

以下目标使用发布构建、推荐配置和本地 SSD 测量：

- 冷启动进入首页：P95 小于 5 秒。
- 打开包含 500 个素材、2,000 个剪辑的项目：P95 小于 10 秒，首屏可交互小于 3 秒。
- 时间线拖动、缩放和选择：正常负载下 P95 输入响应小于 50 毫秒。
- 单路 1080p30 H.264 基础剪辑：完整质量实时播放；复杂效果场景允许自动降至 1/2 或 1/4 预览质量。
- 播放期间音画漂移：连续 30 分钟小于 1 帧。
- 内存与 GPU 缓存必须有明确容量上限，关闭项目后可释放项目级资源。

性能结论必须来自固定样例、同一设备和相同构建的前后测量。

### 8.3 安全与隐私

- 所有外部路径、MCP 参数、项目 JSON、媒体元数据和网络响应均按不可信输入验证。
- MCP 仅监听回环地址，并验证 Origin、内容类型、协议版本、请求大小和会话数量。
- HTTPS 证书错误不可忽略。
- 不记录密钥、令牌、登录凭据、完整用户提示词或不必要的绝对路径。
- 不新增遥测；如保留现有生产遥测能力，默认策略、用户选择和隐私说明必须与 macOS 一致。

### 8.4 可访问性与本地化

- 核心控件具备可读名称、键盘焦点、状态和快捷键提示，可被 Windows Narrator 识别。
- 文本支持缩放，不因 200% DPI 被截断。
- 稳定协议值、项目字段、效果 ID 和 MCP 错误码不本地化。
- UI 文案从统一本地化资源加载，不在业务代码中散落平台专属字符串。

## 9. 兼容性矩阵

每个版本发布前必须维护一份真实测试矩阵，至少覆盖：

- Windows 10 22H2 最新补丁。
- NVIDIA、AMD、Intel 三类 GPU；至少一个纯软件编码回退环境。
- H.264/H.265、8-bit/10-bit、恒定/可变帧率、横竖屏、旋转元数据、含/不含音轨、alpha 素材。
- 44.1/48/96 kHz、单声道/立体声和不同音频设备。
- 本地盘、外接盘、UNC 路径、只读目录、磁盘不足和文件被占用。
- 100% 至 200% DPI、双屏和跨屏移动。
- macOS 创建项目在 Windows 打开，Windows 保存后回到 macOS 打开。

## 10. 测试与验收

### 10.1 自动化测试

- 将当前纯领域测试按行为移植为跨平台黄金测试，包括时间线数学、波纹/覆盖、吸附、链接、嵌套、多机位、关键帧、撤销和项目迁移。
- 使用同一组 JSON 固件分别在 macOS 与 Windows 执行，比较读取后的规范化模型。
- 使用固定媒体夹具比较指定时间点的帧哈希或感知哈希、音频样本误差、字幕布局和最终导出时长。
- 文件测试使用唯一临时目录，不访问用户真实项目，不依赖网络和生产凭据。
- 并发测试通过门闩或可注入钩子确定性控制，不以 sleep 或重试次数作为正确性条件。

### 10.2 MCP 端到端测试

- 启动 Windows MCP 服务，验证工具发现和 schema。
- 创建隔离项目，通过 MCP 导入素材、添加剪辑、设置属性/关键帧、生成字幕、导出并读回状态。
- 独立检查项目 JSON、时间线结果和导出文件，不只信任成功回执。
- 验证无效输入、无变化操作、取消、后台失败、稳定 ID 和一次撤销完整恢复。

### 10.3 手工 UI 验收

至少执行以下场景：

1. 新建项目，导入视频、音频、图片和 Lottie，拖入不同轨道。
2. 完成分割、修剪、滑移、波纹删除、复制粘贴、链接和多选移动。
3. 添加文字、字幕、关键帧、混合模式、LUT、色度键和多个效果。
4. 播放、拖动、逐帧、切换音频设备、最小化、睡眠唤醒和恢复。
5. 保存、自动保存、另存为、关闭、退出、重新打开和媒体重新链接。
6. 使用内置 Agent 和外部 Codex/Claude/Cursor 通过 MCP 修改时间线并撤销。
7. 导出 H.264/H.265，检查分辨率、时长、音画同步、首尾帧和异常中断清理。
8. 在 macOS 和 Windows 间往返打开同一项目。

UI 只有在人工确认后才能标记通过。

### 10.4 发布阻断条件

出现以下任一情况不得发布：

- 保存、另存为、关闭、退出或媒体写入可能造成项目或素材丢失。
- 预览和导出使用不同时间线或效果规则。
- 失败或无变化操作创建撤销步骤。
- 后台任务可提交到已关闭、已切换或已变化的项目。
- MCP 能被局域网访问，或凭据/令牌出现在日志和项目文件中。
- Windows 保存会删除 macOS 仍需使用的未知字段或不支持效果。
- P0 格式在无提示情况下被转码、降级或改变色彩/音频语义。

## 12. 阶段计划与技术验证门

### 阶段 0：架构与风险原型

完成以下原型后再进入完整开发：

- 打开一个真实 `.palmier` 项目并显示多轨时间线。
- 使用 FFmpeg + D3D11 播放一条 1080p H.264 视频并同步输出音频。
- 使用 HLSL 实现变换、透明度、一个混合模式和一个调色效果。
- 导出并验证同一帧的预览/导出一致性。
- 在 Windows 启动本地 MCP 服务并执行一次可撤销的剪辑操作。
- 验证 Qt、FFmpeg、编码器、模型、字体和安装器的许可及分发可行性。

若原型无法证明项目兼容、实时预览、导出一致性和 MCP 复用，应在继续投入前重新选择框架或缩小首版范围。

### 阶段 1：跨平台领域核心

- 项目 schema、模型、时间线运算、校验、编辑操作、撤销和持久化。
- macOS/Windows 共享黄金测试和跨平台项目往返测试。

### 阶段 2：Windows 编辑器基础

- 首页、项目生命周期、媒体库、时间线、预览、检查器、基础音频和 H.264/H.265 导出。
- 达到 P0 非 AI 编辑闭环。

### 阶段 3：高级编辑与 AI

- 字幕、转录、多机位、搜索、降噪、生成式 AI、内置 Agent 和完整 MCP。
- 完成 P1 功能与端到端验证。

### 阶段 4：稳定、性能与发布

- 大项目性能、GPU/驱动矩阵、安装更新、签名、恢复、无障碍、本地化和跨平台兼容。
- 修复所有发布阻断项后进入稳定版。

## 13. 初步工作量判断

本项目不是 UI 外壳移植。SwiftUI/AppKit、AVFoundation、Core Image/Metal、Speech/Core ML/MLX 和 Sparkle 均需要 Windows 实现或替代层；同时必须保留项目、撤销、导出和 MCP 的统一语义。

在完成阶段 0 原型前，不给出固定发布日期。用于资源规划的非承诺估算为：

- 阶段 0：4–6 周。
- 达到 P0 内测：4–6 个月。
- 达到接近当前 macOS 功能完整度：8–12 个月。

估算前提为 5–7 人稳定团队，至少覆盖媒体/GPU、桌面 UI、领域核心、Agent/后端、测试与发布工程。单人或仅做界面移植无法在保持功能完整和数据安全的前提下实现上述范围。

## 14. 待确认决策

进入阶段 0 前需由产品与工程共同确认：

1. Windows 首版是否接受仅支持 x64 和 Windows 10 22H2。
2. P0 是否必须包含多机位、本地转录、本地语义搜索、ProRes 和 HDR。
3. 是否要求 Windows 与 macOS 同一项目双向无损往返，还是仅保证 macOS → Windows 导入。
4. Windows 版是否沿用现有账户、订阅、积分和生成服务。
5. GPLv3 发布方式、Qt/FFmpeg/编解码器/模型/字体的最终许可证组合。
6. 安装包签名证书、更新分发地址和发布渠道。
7. 可接受的最低 GPU、无独显设备的软件回退范围和性能下限。
8. 字体缺失时允许替代，还是要求项目字体打包/嵌入。
